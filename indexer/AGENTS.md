# Indexing System

Code indexing pipeline for BM25 sparse search and Qdrant vector storage.

## Architecture

```
Source Files → AST Chunking → BM25 Index + Qdrant Vectors → Consistent IDs
```

## Key Files

| File | Purpose |
|------|---------|
| `indexer/index_repo.py` | Main indexer - full pipeline orchestrator |
| `indexer/index_repo_v2.py` | Alternate implementation (unused) |
| `indexer/build_cards.py` | Legacy CLI: chunks → cards (blocks on LLM) |
| `indexer/index_stats.py` | Index statistics collector |
| `server/cards_builder.py` | Modern job-based card builder with streaming |

## build_cards vs CardsBuilder

### `indexer/build_cards.py` (Legacy)
- **Synchronous** - blocks on LLM calls
- Reads `chunks.jsonl` → calls `generate_text()` per chunk → writes `cards.jsonl`
- CLI tool: `python -m indexer.build_cards`
- No progress streaming

### `server/cards_builder.py` (Modern)
- **Asynchronous** - job queue with threading
- Dataclass `CardsBuildJob` with SSE progress events
- Real-time progress: scan → chunk → summarize → write → sparse → finalize
- Supports filtering: `exclude_dirs`, `exclude_patterns`, `exclude_keywords`
- API: `POST /api/cards/build/start` → `GET /api/cards/build/stream/{id}`

## Knowledge Cards Structure

```python
Card = {
    'file_path': str,
    'start_line': int,
    'end_line': int,
    'purpose': str,              # One-sentence business purpose (240 chars max)
    'symbols': List[str],        # Function/class names (max 5)
    'technical_details': str,    # Implementation notes
    'domain_concepts': List[str],# Business terms
    'routes': List[str],         # API endpoints (max 5)
    'dependencies': List[str],   # External services
    'patterns': List[str],       # Design patterns
}
```

Cards are **semantic summaries** generated by LLM enrichment. Stored in:
- `{out_dir}/cards.jsonl` - JSON format
- `{out_dir}/cards.txt` - Text format for BM25 indexing

## Indexing Modes

### Hybrid Mode (`SKIP_DENSE=0`, default)
- Requires Qdrant running
- Builds both BM25 sparse index AND vector embeddings
- Enables semantic/hybrid search

### BM25-Only Mode (`SKIP_DENSE=1`)
- No Qdrant required
- Only builds BM25 sparse index
- Faster, no API costs
- Keyword search only

## Consistent ID Mapping

BM25 and Qdrant MUST use the same document IDs:

```python
# Chunk IDs are deterministic from the chunker (file path + node index + snippet)
chunk_id = hashlib.md5((file_path + str(chunk_idx) + ast_node_text[:80]).encode()).hexdigest()[:12]

# Qdrant point IDs are UUID5 derived from the chunk ID
point_id = uuid.uuid5(uuid.NAMESPACE_DNS, chunk_id)

# Store chunk_id in BM25 and payload; store point_id in Qdrant
bm25_index.add(chunk_id, content)
qdrant_client.upsert(collection, points=[Point(id=point_id, vector=embedding, payload={"id": chunk_id})])
```
